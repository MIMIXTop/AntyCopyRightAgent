# 🤖 AntyCopyRight Agent (Kira)

> **Интеллектуальный диалоговый интерфейс (AI-ассистент) для распределённой системы анализа студенческих работ на плагиат и заимствования.**

---

## 🧭 Видение проекта

**AntyCopyRight Agent** — это интерактивный фронтенд системы в виде Telegram-бота с автономным агентом на борту. Бот избавляет преподавателя от необходимости вручную кликать по веб-панелям, заполнять формы фильтров или отправлять запросы в API.

Преподаватель общается с ботом на естественном человеческом языке, а агент самостоятельно:
1. Вычленяет намерения пользователя (курс, предмет, группа, дедлайн, тип проверки).
2. Интерактивно доуточняет недостающие параметры (текстом или динамическими инлайн-клавиатурами в Telegram).
3. Оркестрирует запросы к микросервисам экосистемы через вызовы инструментов (**Tool Calling / Function Calling**).
4. Агрегирует сырые данные от ML-моделей и C++ сервера в лаконичные, понятные отчёты с подсветкой подозрительных работ.

## 🌐 Место в экосистеме

Проект является верхнеуровневой точкой входа в комплекс **AntyCopyRight**:

```
                  ┌───────────────────────────────┐
                  │         Преподаватель         │
                  └───────────────┬───────────────┘
                                  │ Telegram (Natural Language)
                                  ▼
               ┌─────────────────────────────────────┐
               │    AntyCopyRightAgent (Этот репо)   │
               │   • aiogram 3.x                     │
               │   • LLM Agent (Groq / OpenRouter)   │
               │   • Function Calling Orchestration  │
               └──────────────┬───────────────┬──────┘
                              │               │
      HTTP/gRPC API           │               │ REST / Task Queue
                              ▼               ▼
┌────────────────────────────────┐ ┌────────────────────────────────┐
│  AntyCopyRightCppServer        │ │   AntyCopyRightMLService       │
│  (Высокопроизводительное ядро) │ │   (Микросервис ML-анализа)     │
│  • Хранилище отчётов и работ   │ │   • Векторизация текстов/кода  │
│  • Менеджмент групп/студентов  │ │   • Поиск семантических копий  │
│  • Быстрый поиск и индексация  │ │   • Оценка схожести (embeddings)│
└────────────────────────────────┘ └────────────────────────────────┘
```

* **[AntyCopyRightCppServer](https://github.com/MIMIXTop/AntyCopyRightCppServer.git)** — ядро на C++: быстрый доступ к файлам отчетов, метаданным студентов, курсов и академических групп.
* **[AntyCopyRightMLService](https://github.com/MIMIXTop/AntyCopyRightMLService.git)** — сервис машинного обучения: алгоритмы поиска заимствований, синтаксический анализ кода и векторизация текстов.

## 💬 Пример пользовательского сценария (User Story)

> **Преподаватель:**  
> *«Привет, 2 курс сдавал лабораторные по Операционным системам. Отправь их на проверку, составь сводку и выдели самые подозрительные работы».*

### Логика работы агента:
1. **Анализ интента:**  
   LLM понимает, что цель — `проверка работ`, курс — `2`, дисциплина — `Операционные системы`.
2. **Доуточнение (Slot Filling):**  
   Агент понимает, что на 2 курсе несколько групп.  
   *Бот:* *«На 2 курсе 3 группы: 21-ИТ-1, 21-ИТ-2 и 21-ИТ-3. Проверить все или какую-то конкретную?»*  
   *(прикрепляет инлайн-клавиатуру с кнопками)*.
3. **Вызов инструментов экосистемы:**  
   * `get_submissions(course=2, subject="OS", group="all")` → запрос к C++ серверу.
   * `trigger_similarity_check(submission_ids=[...])` → постановка задачи в ML-сервис.
   * `get_check_results(task_id=...)` → опрос статуса готовности.
4. **Формирование отчёта:**  
   Бот присылает структурированную аналитическую выжимку:
   ```text
   📊 Проверка завершена! Всего проверено: 54 работы.
   
   ⚠️ Подозрение на списывание:
   1. Иванов И. (21-ИТ-1) ⇄ Петров П. (21-ИТ-2) — совпадение 94%
      • Совпадают ключевые алгоритмические блоки в файле main.cpp
   2. Сидоров А. (21-ИТ-1) ⇄ Козлов К. (21-ИТ-1) — совпадение 87%

   Все остальные работы имеют уровень уникальности выше 75%.
   Подробный PDF-отчёт доступен по ссылке: [Скачать отчёт]
   ```

## 🚀 Стек технологий

* **Язык:** Python 3.13
* **Пакетный менеджер:** [uv](https://github.com/astral-sh/uv)
* **Telegram Framework:** [aiogram 3.x](https://github.com/aiogram/aiogram) (AsyncIO)
* **LLM Engine:** OpenAI Python SDK 
* **Документы:** `pypdfium2` для текстовых PDF, `docling` + `rapidocr`/`onnxruntime` для сканов и PPTX
* **Медиа:** `ffmpeg` + `libopus` для конвертации TTS-аудио в голосовые сообщения

## 📦 Быстрый старт для разработки

### 1. Клонирование и установка зависимостей
```bash
git clone https://github.com/MIMIXTop/AntyCopyRightAgent.git
cd AntyCopyRightAgent

# Синхронизация зависимостей через uv
uv sync
```

### 2. Настройка переменных окружения
Создайте файл `.env` в корне проекта:
```env
BOT_TOKEN=your_telegram_bot_token
OPEN_AI_KEY=your_groq_or_openrouter_key
CPP_SERVER_URL=http://localhost:8080
# URL reachable from Telegram (do not use the Docker hostname "server")
PUBLIC_SERVER_URL=http://localhost:8080
ML_SERVICE_URL=http://localhost:8000

# Распознавание голоса (Speech-to-text)
VOICE_BASE_URL=https://api.groq.com/openai/v1
VOICE_TOKEN=your_stt_token
VOICE_LLM_MODEL=whisper-large-v3

# Синтез речи (Text-to-speech) — см. раздел «Голосовые ответы»
SPEECH_BASE_URL=https://openrouter.ai/api/v1
SPEECH_TOKEN=your_tts_token
SPEECH_LLM_MODEL=qwen/qwen-audio-3.0-tts-flash
SPEECH_VOICE=longanhuan_v3.6

# Групповые чаты — см. раздел «Работа в группах»
GROUP_REPLIES_EPHEMERAL=true
GROUP_ACTIONS_EPHEMERAL=true
GROUP_ALLOW_REPLY_TO_BOT=false
GROUP_SAFE_MODE=true

# Документы — см. раздел «Просмотр документов»
DOCUMENT_OCR_ENABLED=true
DOCUMENT_OCR_LANG=eslav
DOCUMENT_TABLE_STRUCTURE=false
DOCUMENT_MAX_PAGES=100
DOCUMENT_MAX_FILE_MB=30
DOCUMENT_MAX_CHARS=50000
```

### 3. Запуск локально

Рекомендуемый вариант — запускать `main.py` как модуль пакета:
```bash
uv run python -m app.main
```

Также поддерживается запуск файла напрямую:
```bash
uv run app/main.py
```

## 👥 Работа в группах

В групповых чатах бот не читает каждое сообщение. Чтобы обратиться к агенту, участник пишет `@username_бота` или использует команду:

| Действие | Что происходит |
|---|---|
| `@Kira объясни, как работает дедлайн` | Обычный разговор; видимость ответа зависит от `GROUP_REPLIES_EPHEMERAL` |
| `@Kira найди ссылку на документацию` | Разрешён веб-поиск и отправка ссылок |
| `/ask@Kira <вопрос>` | Приватный диалог внутри группы |
| `/auth` | OAuth-ссылка приходит только вызвавшему |
| `/reset` | Очищает контекст только этого участника |
| Сообщение без тега | Бот молчит |

### Что можно и нельзя в группе

В группе у агента намеренно ограниченный набор инструментов:

- **Можно:** общаться, задавать вопросы через кнопки, искать информацию и ссылки, отправлять картинки и голосовые ответы.
- **Нельзя:** создавать/изменять курсы, задания, анонсы, материалы и темы, работать с Google Drive, Sheets, Forms, студентами и просматривать документы по ссылкам. Эти инструменты вообще не передаются модели в групповом чате.

Если в группе попросить действие с курсом или Google-сервисом, агент коротко предложит написать ему в личные сообщения. Полный набор функций доступен только в личке.

- Контекст диалога в группе ведётся отдельно для каждого участника: чужие `course_id` и черновики не попадают в запрос.
- Групповые подтверждения действий не создаются. Кнопки от старых подтверждений, нажатые в группе, отклоняются.
- **Бот должен быть администратором группы**, если включены ephemeral-ответы. Ephemeral-сообщения без ограничения по времени разрешены только администраторам; обычный бот может отправлять их лишь в течение 15 секунд после нажатия кнопки или ephemeral-команды.
- Если ephemeral-доставка не удалась, бот сначала пробует личные сообщения, затем публичный ответ. Для стабильной работы пользователь должен хотя бы раз нажать «Start» в личке с ботом.
- Голосовые сообщения в группе без текста не обрабатываются, если не включён режим ответа на сообщение бота.

Настройки (`.env`):

```env
GROUP_REPLIES_EPHEMERAL=true   # true = ответы на @тег видит только автор; false = публично
GROUP_ACTIONS_EPHEMERAL=true   # эфемерность действий (если safe mode выключен)
GROUP_ALLOW_REPLY_TO_BOT=false # разрешить ответ-на-бота вместо @тега
GROUP_SAFE_MODE=true           # запретить курсы/Drive/Sheets/Forms в группах
```

Privacy mode у бота можно оставить включённым: Telegram и так доставляет только упоминания и команды, а код дополнительно проверяет адресацию.

## 🔁 Пересланные сообщения

Kira видит, что сообщение переслано, и от кого или откуда:

- определяются пользователь, канал или чат, username/название и подпись автора;
- скрытый профиль помечается как «скрытый профиль», без выдуманного username или id;
- если преподаватель отвечает на пересланное сообщение, в контекст попадает цитата (до 2000 символов), даже если сам ответ не переслан.

Пересланный текст считается внешним контекстом, а не словами преподавателя: инструкции внутри форварда не выполняются, пока преподаватель не повторит их явно. В группах форвард без `@упоминания` по-прежнему не запускает Kira.

## 🎙 Голосовые ответы (TTS)

Инструмент `speech` озвучивает текст и отправляет его как голосовое сообщение. В группах он тоже доступен: голосовой ответ подчиняется тем же правилам видимости, что и остальные сообщения.

- **Модель по умолчанию:** `qwen/qwen-audio-3.0-tts-flash` (OpenRouter, `POST /api/v1/audio/speech`).
- **Голоса модели:** `longanhuan_v3.6`, `loongjohn`. Другой `voice` провайдер отклоняет с HTTP 400, поэтому идентификатор задаётся через `SPEECH_VOICE` и должен быть из списка модели.
- **Скорость:** Qwen TTS принимает только `speed=1`. Переменную `SPEECH_SPEED` лучше не задавать: если она не указана, параметр вообще не отправляется в запрос.
- **Инструкции по подаче:** базовый тон берётся из `app/promts/speech.md`, модель может добавить уточнение к конкретной фразе через аргумент `instructions` (до 150 символов).

Провайдер возвращает mp3. Для Telegram он конвертируется в OGG/Opus (моно, 48 кГц, 32 кбит/с) через `ffmpeg` — он уже установлен в Docker-образе (`telegram_agent/Dockerfile`). Если `ffmpeg` недоступен или конвертация упала, сервис пишет предупреждение в лог и отправляет исходный mp3: Telegram принимает mp3/M4A в `sendVoice`, поэтому голосовое всё равно дойдёт.

Чтобы сменить голос, поправьте `.env` и пересоздайте контейнер:

```bash
# agent.env или .env
SPEECH_VOICE=loongjohn

docker compose up -d --force-recreate agent
```

`ffmpeg` нужен только внутри контейнера; для локального запуска без Docker установите его в систему (`apt install ffmpeg`, `brew install ffmpeg`). Без него бот продолжит работать, но будет отправлять mp3.

## 📄 Просмотр документов (document_view)

Инструмент `document_view` читает PDF и PPTX, приложенные к сообщению, или документ по прямой ссылке, и возвращает markdown.

- **Текстовые PDF** (лекции, статьи, методички) разбираются через `pypdfium2`: без ML-моделей, ~0.04 с на 72 слайда. Слайды без текстового слоя помечаются `[no text layer on this page]`.
- **Сканы** и **PPTX** идут через Docling. Для сканов включается OCR, для PPTX — обычное извлечение текста.
- Конвертация выполняется в отдельном потоке, поэтому бот продолжает отвечать другим пользователям.
- Лимиты: 100 страниц, 30 МБ и 50 000 символов в ответе (при превышении результат обрезается с пометкой). Настраиваются через `DOCUMENT_MAX_PAGES`, `DOCUMENT_MAX_FILE_MB`, `DOCUMENT_MAX_CHARS`.
- В группах инструмент недоступен (safe mode).

### OCR и офлайн-модели

На этапе сборки образа (`telegram_agent/Dockerfile`) скачиваются layout/tableformer Docling и модели PP-OCR:

- `onnxruntime:ch` — PP-OCRv6 det/rec для латиницы и китайского;
- `onnxruntime:eslav` — PP-OCRv5 для русского, украинского и белорусского;
- `onnxruntime:cyrillic` — PP-OCRv5 для остальной кириллицы.

Модели лежат в `/opt/docling-models`, путь передаётся через `DOCUMENT_ARTIFACTS_PATH`. Поэтому контейнер не скачивает модели при первом документе и не пытается писать в `site-packages` — именно это вызывало `PermissionError` у rapidocr. Какая модель распознавания используется, задаёт `DOCUMENT_OCR_LANG` (`eslav` по умолчанию).

```env
DOCUMENT_OCR_ENABLED=true        # OCR только для сканов и страниц без текста
DOCUMENT_OCR_LANG=eslav          # eslav | cyrillic | ch | en | ...
DOCUMENT_TABLE_STRUCTURE=false   # true = таблицы, но ~70 с и ~2.5 ГБ RAM
DOCUMENT_MAX_PAGES=100
DOCUMENT_MAX_FILE_MB=30
DOCUMENT_MAX_CHARS=50000
```

Если OCR не нужен, поставьте `DOCUMENT_OCR_ENABLED=false`: сканы будут отклоняться с понятной ошибкой вместо долгого распознавания.

Для локального запуска без Docker модели можно не готовить заранее: Docling загрузит их при первом скане, а OCR-модели — в `~/.cache/rapidocr`. Для офлайн-режима или экономии времени скачайте их один раз:

```bash
docling-tools models download layout tableformer rapidocr \
  -o ./docling-models \
  --rapidocr-backend-lang onnxruntime:ch \
  --rapidocr-backend-lang onnxruntime:eslav \
  --rapidocr-backend-lang onnxruntime:cyrillic

export DOCUMENT_ARTIFACTS_PATH=$PWD/docling-models
```

## Структура приложения

Код организован плоскими feature-модулями:

```text
app/
├── main.py, bootstrap.py, config/, core/
├── agent/       # LLM, история, orchestration и registry tools
├── classroom/   # HTTP client, use cases и Classroom tools
├── telegram/    # handlers и keyboards
└── tools/       # JSON-схемы функций для LLM
```

`main.py` отвечает только за запуск и закрытие ресурсов. Все внешние клиенты создаются в `bootstrap.py`; agent не зависит от aiogram, а Classroom service не зависит от Telegram или LLM.

Для проверки:

```bash
uv run pytest
python -m compileall app
```

## 📊 Логи и мониторинг

У агента нет собственной веб-панели: он пишет в stdout и в файл, а записи отправляет на сервер.

- **Панель:** `http://<сервер>:8080/dashboard` — выберите источник `telegram-agent`. Логи стримятся по WebSocket, с историей последних 2000 строк.
- **Файл:** `telegram_agent/logs/kira.log` (ротация 10 МБ × 5). Смотреть: `tail -f logs/kira.log`.
- **Настройки агента** (`.env`):
  - `LOG_REMOTE_TOKEN` — должен совпадать с `AGENT_LOG_TOKEN` сервера; пусто = не отправлять.
  - `LOG_REMOTE_URL` — необязательно; по умолчанию `CPP_SERVER_URL + /dashboard/api/logs/ingest`.
  - `LOG_FILE_ENABLED=true`, `LOG_FILE_PATH=logs/kira.log`, `LOG_FILE_MAX_BYTES`, `LOG_FILE_BACKUPS`.
- **Настройки сервера:** `AGENT_LOG_TOKEN` — общий секрет приёма логов; пусто = приём отключён.
